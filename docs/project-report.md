## 1 摘要

本报告的任务，是说明我如何把一条可公开访问的短视频页面写成可审计的分层记录，并在生产站点的 Postgres 库上做描述性分析，而不是把平台推荐分数或语言模型输出直接当作营销因果结论。

既有做法的技术困难在于：页面计数、内容手法与观影后的个人判断常被写入同一组标签；缺测容易被改写成 0；跨平台计数被直接比较。其结果是记录无法复现，人工内容标签与 AI 建议也无法分列对照。

本文的处理思路是：先把分析对象定义成带稳定编号的公开视频，再按元数据、内容、个人反应与 AI 标注四层填写；取值由数据字典约束；分析只在同一 `meta_platform` 内、成对删除缺测之后报告描述性共现与秩相关。

第一项技术贡献是四层视频模型。生产库中元数据层 14 个字段、内容层 8 个、个人反应层 4 个、AI 层 10 个，合计 36 个字段键；其作用是使公开事实、人工内容、个人反应与 AI 建议在同一条 `video_id` 上分列存放。

第二项技术贡献是三本受控字典。内容字典 8 个字段、44 个条目，观众字典 4 个字段、18 个条目，AI 字典 9 个字段、48 个条目；其作用是使 AI 不能另造一套 code 体系。

第三项技术贡献是公开 HTML 采集、同平台比率、四组 Spearman 配对以及四张预设桑基对应图。其作用是把计算公式与对应规则写进 `web/lib/analysis.ts` 与 `web/lib/content-reaction-sankey.ts`，有效配对少于 3 时不报告系数。

截至 2026-10-27，生产库 `videos` 表有 31 条记录，全部为 `source_kind=collected` 且 `meta_platform=bilibili`，`ai_label_status` 均为 `labeled`，8 个人工内容字段与对应 AI 字段的对照对数为 248、一致率为 1。31 条均有正播放量，点赞率均值 0.0399、中位数 0.0368。按站点实现的平均秩 Spearman，信任×点赞率 \(\rho=0.024\)，记忆×点赞率 \(\rho=-0.019\)，行动意愿×互动率 \(\rho=0.146\)，信任×互动率 \(\rho=0.018\)（\(n=31\)）。这些读数支持「合同已落地、本库可计算」，不支持把 AI 层当作独立金标准，也不支持由相关推出因果。`tests/` 中 8 个测试函数只核验包导入、字典解析与 API schema。

## 2 引言

本节说明研究任务。短视频营销分析的输入是一条可公开访问的视频页面，输出应是分层字段、受控字典取值，以及仅在同平台、成对删除缺测之后才计算的描述性统计。

本节说明该任务的应用意义。课程评审需要能够核査：哪些 Hook 与叙事与完看、记忆一同出现；哪些证据与说服与信任一同出现；哪些漏斗阶段与行动号召与行动意愿一同出现；以及人工内容标签与 AI 建议在哪些字段上能够对照。

本节指出既有做法难以提供上述输出。平台推荐依据停留等行为推断兴趣标签；运营报表把播放量与点赞量直接当作内容质量。两者都不把「页面上有什么」「片子如何组织信息」「我观影后如何判断」写成可复查的三列。

本节分解本项目要解决的技术难点。第一，事物边界不清，一条视频缺少稳定编号、公开链接与入选理由。第二，字段混层，内容类型与播放量、信任感写在同一轴上。第三，取值不受控，自由文本无法与 AI 建议做字符串相等对照。第四，把跨平台计数或单条视频上的共现写成因果。

本节给出处理管道。我先冻结最小必填项与四层默认模型，再冻结三本字典，然后只采集公开 HTML 中的元数据、简介与可见评论，最后用比率、一致率与桑基对应显示「一起出现」，而不估计总体、不声称因果。

本节预告验证材料。验证以生产站点 Neon 库中的 31 条视频及采集、字典、模型表为分析总体；仓库内的 8 个测试函数只用于结构核验。仓库 `data/sample/` 中的公开 CSV 未写入本库，因此不作为本节统计的分子或分母。

## 4 网站系统

### 4.1 网站内容

本段说明站点面向课程分析的功能范围。生产地址为 https://lucy-short-video-marketing-analytic.vercel.app/collections ；站点根路径重定向到 `/videos`。导航提供视频库、分析、视频模型、数据字典、数据采集与模型配置六类页面，并提供中英文切换。

本段说明各页面承担的记录职责。`/videos` 列出已入库视频并支持手工新建与分层编辑。`/collections` 以关键词在公开站点检索、分批抓取元数据、调用模型写 AI 层，再导入 `videos`。`/analysis` 读取全部视频，展示内容类型饼图、比率公式、衍生对照表、四张内容—反应桑基图以及人机一致率。`/model` 与 `/dictionaries` 维护四层字段与三本字典。`/model-config` 保存 OpenAI 兼容接口的密钥、优先级与超时，不在页面上展示密钥明文。

### 4.2 搭建过程

本段说明仓库如何成为可访问站点。应用代码位于 `web/`，由 GitHub `main` 触发 Vercel Git 部署；Root Directory 设为 `web`。`DATABASE_URL` 仅作为服务端环境变量注入，对应 Neon 池化连接，不以 `NEXT_PUBLIC_` 暴露给浏览器。

本段说明模式如何进入生产库。Alembic 迁移仍由仓库内 Python 包维护，用于在 Neon 直连主机上演进表结构；Next.js 启动时 `ensureAppSchema` 以 `CREATE TABLE IF NOT EXISTS` 与 `ALTER TABLE ... ADD COLUMN IF NOT EXISTS` 保证采集与 `extra` JSONB 等列存在。FastAPI 包保留给本地脚本与迁移，不是生产 Web 服务器。

### 4.3 技术架构

本段给出运行时分层。浏览器只访问同源 App Router 页面与 `/api/v1/*` Route Handler；Route Handler 通过 Node 运行时的 `pg` 连接池读写 Neon。页面设置 `dynamic = "force-dynamic"` 与 `runtime = "nodejs"`，分析页直接 `listAllVideosDb()`，避免把库内容静态化到 CDN。

本段给出数据对象在库中的落点。`videos` 存分层记录，`extra` JSONB 存 `ai_summary` 等非列字段；`video_model_layers` 与 `video_model_fields` 存可编辑模型；`dictionary_sets`、`dictionary_fields`、`dictionary_items` 存字典；`collection_jobs`、`collection_batches`、`collection_items` 存采集任务、批次与条目，其中 AI 草稿在 `collection_items.ai_payload`。`model_api_keys` 仅服务端读写。

本段给出采集与标注的数据流。任务按采集数量拆成至多 5 个批次并行请求公开 HTML；解析 JSON-LD、Open Graph 与页面可见评论；AI 阶段时限 300 秒，先根据标题、简介与热度靠前的可见评论写简介，再只根据简介填写与内容层相同的 code。导入接口把元数据与 AI 列写入 `videos`，不自动覆盖人工内容列与个人反应列。

### 4.4 使用指南

本段说明语言与入口。首次访问默认中文（`locale` cookie 缺失时）；导航中的语言开关写入 cookie 并刷新当前路径。分析工作从 `/collections` 新建任务开始：填写任务名、站点 URL、关键词与拟采集条数，保存后执行运行。

本段说明从采集到分析的操作顺序。运行完成后打开批次中的条目，核对照片标题、计数与 AI 简介；确认公开链接与标题齐全后导入视频库。随后在 `/videos/[id]/edit` 填写或修订内容层与个人反应层。打开 `/analysis` 查看当前库上的分布、比率、桑基与一致率。字典或模型字段若需增补，先改 `/dictionaries` 或 `/model`，再回头改视频，以免出现字典外 code。

本段说明不可在界面上完成的操作。站点不提供登录平台账号、不调用评论私有接口、不把缺测显示为 0、不在有效配对少于 3 时输出 Spearman 系数。密钥只在模型配置页写入，不进入 git。

## 5 问题表述

本段给出形式化任务。令一条视频为对象 \(v\)。我要构造记录 \(R(v)=(M,C,U,A)\)，其中 \(M\) 为公开元数据，\(C\) 为人工内容标签，\(U\) 为我的个人反应，\(A\) 为 AI 建议；\(C\) 与 \(A\) 使用同一套内容 code。

本段给出允许的分析。在同一 `meta_platform` 内，对成对均非空的 \((U_i,\mathrm{rate}_j)\) 计算 Spearman \(\rho\)，有效对少于 3 则状态为 `insufficient`；对人机均非空的 8 个内容字段计算一致率；对预设的内容字段到反应字段计数，绘制 4 张桑基图。

本段给出明确禁止。禁止把缺测写成 0；禁止跨平台比较播放量；禁止由桑基线宽或 \(\rho\) 推出「某种 Hook 导致完看」；禁止把 AI 填进金标准意义上的 \(C\)。

本段对应 `docs/AuthoritativePlan.md` 中的研究问题。本报告只回答这些问题在 2026-10-27 生产库上「能否计算、算出了什么」，不把计划中的跨平台 Gold 样本写成已经完成。

## 6 方法

### 6.1 总览

本段设定方法场景。输入是公开链接与我完成观影后的判断；输出是分层记录和描述性图表。

本段说明核心做法。核心是「先定义事物，再建模字段，再用字典约束取值，最后按规则采集与对照」。

本段对应后文小节。6.2 定义事物，6.3 分层字段，6.4 字典，6.5 采集，6.6 关联与对应。

### 6.2 定义研究对象

本段说明动机。若不以「一条有编号的公开视频」为事物，后续字段会落到账号、话题或某次推荐曝光上，记录无法按 URL 复现。

本段说明做法。`video_id` 匹配 `^[A-Z0-9_-]+$`；必须有平台枚举 `douyin` / `xiaohongshu` / `bilibili`、公开 URL、标题、真实公开昵称、发布日期和入选理由；表现数字必须带采集时间。最小必填集见 `data/data_dictionary.md`。采集导入使用 `C` + 上海时区日期 + 条目号生成编号，入选理由写为「数据采集导入」。

本段说明优点。事物边界固定后，元数据只对照页面，内容层与个人反应层必须在观影后填写，AI 只能作为第四层建议。

### 6.3 分层建模与字段

本段说明动机。页面数字回答不了开头如何组织注意；标题回答不了信任判断。若不分层，一致率与桑基会把不同问题混在一根轴上。

本段说明做法。默认模型与生产库一致：元数据 14、内容 8、个人反应 4、AI 10（含 `ai_summary`），合计 36 个字段键。`ai_summary` 不作为 `videos` 表列，而进入 `videos.extra`。内容层 8 个字段与 AI 层对应字段共用字典 code。

本段说明优点。分层使内容类型留在内容层，点赞计数留在元数据层，信任分数留在个人反应层，AI 建议不能在导入时覆盖人工列。

### 6.4 数据字典

本段说明动机。没有受控取值，Hook 会写成任意短句，AI 建议无法与人工标签做字符串相等对照。

本段说明做法。生产库内容字典 8 字段 44 条目，观众字典 4 字段 18 条目，AI 字典 9 字段 48 条目。对照时只比较 code；枚举不在字典中则丢弃。

本段说明优点。AI 与人工使用同一 code 表，一致率的分母是「两边都已填写的配对数」，而不是「模型自称正确的条数」。

### 6.5 数据采集

本段说明动机。登录或调用评论私有接口会越过公开数据边界；只保存标题又无法写 `ai_summary`。

本段说明做法。采集只请求公开 HTTP(S) HTML。每个任务的拟采集条数最多拆成 5 个批次并行；AI 阶段时限 300 秒。无简介且无可见评论时保持 `not_labeled`。导入把 AI 草稿写入 AI 列，内容层与个人反应层仍须在视频编辑页填写。

本段说明优点。元数据在没有模型密钥时也可以落库；AI 失败时简介仍可保留并进入 `needs_review` 或 `failed`，不回写内容层。

### 6.6 关联度量与内容—反应对应

本段说明动机。研究问题问的是「一起出现」，不是「导致爆款」。若把不同平台的播放量放进同一个 \(\rho\)，系数没有解释。

本段说明做法。点赞率、评论率、收藏率、分享率、互动率只在播放量存在且不为 0 时计算；互动率还要求点赞、评论、收藏、分享四个分子均非空。Spearman 使用平均秩后的 Pearson 相关，配对固定为信任×点赞率、记忆×点赞率、行动意愿×互动率、信任×互动率；`MIN_PAIRS = 3`。桑基图固定 4 张：Hook 与叙事到完看；Hook 与叙事到记忆；证据与说服到信任；漏斗与 CTA 到行动意愿。线宽是两边都填写的视频条数。

本段说明优点。规则写在分析库中，不能在页面上改成因果检验；样本不足时状态为 `insufficient`，而不是输出一个看起来精确的 \(\rho\)。

## 7 验证

### 7.1 设置、库表规模与样本构成

本段固定验证总体。以下计数全部来自 2026-10-27 的生产库，而不是仓库 CSV。Gold 30 条仍是方法论文档中的目标，不是本库的抽样框标签。

本段报告对象规模。`videos` 31 行；`collection_jobs` 3 行；`collection_batches` 21 行；`collection_items` 92 行，其中不重复公开 URL 75 个，已写入 `imported_video_id` 的 36 条，其中 5 个导入编号在 `videos` 中已不存在。因此分析总体是当前仍在 `videos` 中的 31 条，不是历史导入的 36 条。

本段报告采集任务构成。任务 1 名为「bilibili-电影解说」，关键词「欧美电影解说」，拟采集 10，实际 5 个批次、批次 `item_count` 合计 21。任务 2 名为「bilibili-美食」，关键词「特色美食」，拟采集 5，4 个批次、合计 35。任务 3 名为「bilibili-补采-10126」，关键词「手工diy」，拟采集 3，12 个批次、合计 36。三个任务的 `site_url` 均为 `https://www.bilibili.com`。

### 7.7 比率与 Spearman 相关

本段核对接力条件。Bilibili 单平台、31 对均有信任、记忆、行动意愿与点赞率、互动率，\(n=31\ge 3\)，状态为 `ok`，可以报告系数。系数按 `web/lib/analysis.ts` 的平均秩 Spearman 计算，以便与站点公式一致。

本段报告四组系数。信任×点赞率 \(\rho=0.024\)；记忆×点赞率 \(\rho=-0.019\)；行动意愿×互动率 \(\rho=0.146\)；信任×互动率 \(\rho=0.018\)。前两组与第四组接近 0；行动意愿与互动率同向但绝对值仍低。结合 7.3 节，互动率几乎由点赞率决定，因此第四组与第一组同向接近是公式上的预期，不是新的独立发现。

本段给出解释边界。\(\rho\) 是 31 条 Bilibili 公开页快照上、我的个人反应分数与页面比率之间的秩相关。它不估计青年用户总体，也不表示提高信任会产生点赞。单条 9 503 595 播放的记录会强烈影响均值，但对秩相关的影响是改变名次而非把均值当作典型值。

### 7.8 人机一致率及其解释边界

本段报告对照规模。8 个字段在 31 条上均为双侧非空，对照对数 `compared = 248`，相等对数 `matched = 248`，总体一致率 1。31 条 `ai_label_status` 均为 `labeled`，31 条 `extra.ai_summary` 非空，且 31 条简介文本均包含「评论」字样，与「简介写入可见评论」的采集设计相符。

本段报告导入路径对独立对照的限制。`importCollectionItemsDb` 只把 AI 草稿写入 AI 列，并不自动填写 `content_*`。因此一致率 1 不是导入函数的算术必然结果。它表明：当前库中人工内容层与 AI 层在字符串上完全相同。可能的生成过程包括独立标注恰好全部重合，也包括观影后把 AI code 接受为内容层。本报告没有第二条独立标注员，因而不能把 1 解释为「模型达到了人工理解」。

本段对应摘要与引言中的主要命题：分层字段已在库中填满（31 条四层均可读）；缺测不作 0（粉丝与收藏的 0 被当作解析快照，播放量为正故比率可算）；字典与测试可核对（8 个测试函数；库内 8/4/9 字段）；AI 未升格为金标准（一致率 1 但独立性未证明）；关联保持描述性（四组 \(\rho\) 已报，不写成因果）。

## 8 结论

### 8.1 AI 对视频理解的能力

本段限定「能力」的含义。这里的能力不是模型在公开基准上的分数，而是本系统允许模型看到什么、写入哪一层、如何与人工标签对照。

本段总结设计给出的能力边界。模型只根据公开 HTML 中的标题、简介和可见热评写简介，再只根据简介填与内容层相同的 code；不登录、不调用评论私有接口、导入时不写入 `content_*`。31 条简介均能写到「评论」相关内容，说明可见评论作为输入时，生成管道可以产出非空 `ai_summary` 并把状态标为 `labeled`。

本段总结测量结果。在 248 个字段—视频对照上，AI code 与内容层 code 完全相同。该结果证明对照仪器已经产生读数，不证明模型独立理解了画面：输入不含视频像素与音频，只含页面文本；内容层与 AI 层是否独立填写无法从当前表结构识别。

本段总结失败如何被记录。状态机包含 `not_labeled`、`labeled`、`needs_review`、`failed`。本快照中 31 条均为 `labeled`，因此失败路径在本库上没有观测频数，不能外推为「采集总是成功」。

### 8.2 视频数据分析得到的结论

本段重申分析单位。结论只关于生产库中 31 条 Bilibili 公开页记录，创作者 27 人，检索入口为三个关键词任务。不能外推到抖音或小红书，也不能外推到青年用户总体。

本段总结内容结构。样本以美食测评、旅行 vlog 与知识讲解为相对多数；Hook 集中在冲突对比、结果前置与强视觉；漏斗以认知阶段为主（25/31）；CTA 以 none 为主（27/31）。个人反应上完看 22/31，记忆与信任集中在 3–4 分，行动意愿没有 4–5 分。把这些层放在一起读：本库视频多数被我标成「看完且记得、中等信任、行动意愿偏低」的认知向内容。

本段总结共现而不是效应。问题—解决叙事与问句 Hook 在本库中与完看完全重叠（5/5 与 3/3）；知识讲解四条全部完看且信任、记忆最高、行动意愿最低；旅行 vlog 点赞率与行动意愿最高。过程证据与口头证据的平均信任接近（约 3.56 对 3.43）。这些是列联计数，不是处理效应。

本段总结比率与相关。在收藏与转发解析为 0 的前提下，互动率近似点赞率；信任、记忆与点赞率的 Spearman 接近 0；行动意愿与互动率 \(\rho=0.146\)。页面热度与我的信任、记忆分数在本库中几乎不一起升降。

本段收束方法对客观事物的处理。我把短视频定义成可编号的公开对象，用四层字段和字典描述它，用公开采集填充元数据与 AI 建议，用观影后的人工层填充内容和反应，用成对计数与秩相关而不是因果检验连接这些字段。下一步仍是按同一合同补入其他平台、并做独立于 AI 层的内容复标，而不是在 \(n=31\)、单平台、一致率 1 的条件下加大因果语气。
